### Features

- **glm**: add Zai GLM Coding OAuth login. The provider moved from `apikey`-only to dual-auth (`oauth` + `apikey`), so a Z.ai account can be added from the dashboard instead of pasting a key by hand. Ports the ZCode CLI polling flow from upstream `decolua/9router` (`src/lib/oauth/providers/glm.js`): `POST zcode.z.ai/api/v1/oauth/cli/init` mints a one-off poll bearer and returns a browser `authorize_url`, the browser signs in, and `GET …/cli/poll/<flow_id>` reports `pending` until it reports `ready`. The Z.ai OAuth token is then exchanged for a platform business JWT (`api.z.ai/api/auth/z/login`) and used to mint a long-lived coding-plan key via `getCustomerInfo` → default org + non-team project → `api_keys` list/create(`zcode-api-key`) → copy. That composite `apiKey.secretKey` is what authenticates model traffic, which is why it — not the OAuth token — is stored in `data.apiKey`. The business JWT and ZCode token ride along in `providerSpecificData` for quota and debugging. Adds the coding-plan quota endpoint (`api.z.ai/api/monitor/usage/quota/limit`) to the provider registry.

  This is not RFC 8628 device code and carries no PKCE: the browser never redirects to a local listener, and the poll bearer must survive from `start` to `poll`. It rides the existing device transport because the envelope it returns (`device_code` = flow id, `verification_uri` = authorize URL) is exactly what the dashboard's device modal already drives, and the poll token is parked in the round-tripped `session` the same way kimi carries its device id.

  Note the lifetime: the Z.ai OAuth token has no refresh grant, so an expired login means re-running the flow — the same behaviour as the official CLI. The coding-plan key itself does not expire, so a completed login does not rot.

  Verified with `go test ./internal/handlers/oauth/ ./internal/providers/` (offline; the live check is gated behind `NINE_ROUTER_LIVE_OAUTH=1`) and `make vet-svelte` at the pinned baseline. The live check opens a real flow against `zcode.z.ai`, asserts the authorize URL targets the Z.ai console, and asserts an unauthorized flow polls as `pending` rather than erroring — it never signs in and mints no credential.
